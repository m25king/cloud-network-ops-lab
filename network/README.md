## 部署顺序

1. 在eNSP建立接线表所示拓扑；保存原始空拓扑，确认设备全部启动。
2. 依次加载WAN-SW、ISP、接入交换机、核心、出口、分支配置。逐段粘贴，遇不支持命令立即停止并记录，不以静态检查替代设备验证。
3. 检查业务VLAN、MSTP区域、Trunk；CORE1是实例1根，CORE2是实例2根。中转接口采用Access加Vlanif，避开部分S5700不支持undo portswitch的问题。
4. 检查OSPF邻居：两核心各2个Full，两个HQ路由器各3个Full，BR各1个Full。业务VLAN使用silent-interface，发布路由但不建立邻居；两核心均发布5个业务网段。
5. 检查VRRP：VLAN10/20/99在CORE1主用，30/40在CORE2主用；主备抢占延时20秒。终端网关始终使用.254。
6. 静态PC先测试，随后测试DHCP；分别从办公和访客测试203.0.113.10。出口AR1发布cost10默认路由、AR2发布cost100；默认路由存在才发布，未使用always。
7. 在每台设备用户视图执行save并确认；导出display current-configuration，另存拓扑，记录版本。configs内文件是构建输入，eNSP导出文件才是实测配置。

## 工程边界与容易被追问的点

- VRRP保护用户网关；MSTP处理二层环路，两者不互相替代。根桥和主网关对齐减少绕行，但上行OSPF仍独立选路。
- DHCP仅在CORE1；两分支各一个上联；ISP、WAN-SW、各PC接入链路仍是单点。只能写“核心网关与接入上联冗余”，不能写“全网无单点”。
- AR出口NAT未同步状态，出口切换后已有连接可能中断；新连接成功不代表会话无损。
- 静态默认路由不检测远端黑洞。断对端设备可能仍保留父物理口UP，默认路由不会自动撤销。本版未实现NQA/BFD联动，不承诺双出口端到端自动容灾。
- VRRP未跟踪上行可达性，核心上行全失但Vlanif存活可能黑洞；这是待改进项。不能因为主备状态正常就认为业务一定正常。
- ACL3000是访客源方向的无状态过滤，不是防火墙会话策略，也没有落实生产设备管理面的完整访问控制。CORE本机协议处理及DHCP报文与VLANIF过滤行为需要在当前镜像实测。
- 没有配置公网DNS。若要演练DNS异常，先自建真实可响应的实验DNS，再增加案例，不把公网测试地址当DNS。
- 没有生产电网连接、调度业务、IEC61850设备或南方电网内部数据。业务区划分只体现通用IP网络能力。
