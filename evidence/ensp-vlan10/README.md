# eNSP 最小VLAN实验：已完成的实测

2026-09-08，实际导入4台设备的拓扑并连接本机交换机控制台，核对型号、VRP版本和接线端口后下发VLAN10配置。S5700作为CORE1，S3700作为ACC1，另有两台模拟PC。

| 链路 | 配置 |
|---|---|
| CORE1 GE0/0/1 ↔ ACC1 GE0/0/1 | Trunk允许VLAN10 |
| CORE1 GE0/0/4 ↔ PC-B | Access VLAN10；PC-B为192.168.10.12/24 |
| ACC1 E0/0/1 ↔ PC-A | Access VLAN10；PC-A为192.168.10.11/24 |

为了直接从设备控制台验证通信，CORE1与ACC1分别增加Vlanif10地址192.168.10.252/24、192.168.10.253/24。这是START_HERE纯二层练习之外的验证接口；两台PC仍在同一子网，无需默认网关。

| 发起设备 | 目标 | 本次结果 |
|---|---|---|
| CORE1 | PC-A，192.168.10.11 | 发送3，收到3 |
| CORE1 | PC-B，192.168.10.12 | 发送3，收到3 |
| ACC1 | CORE1，192.168.10.252 | 发送3，收到3 |

原始命令与返回文本见[CORE1记录](console-2100.json)、[ACC1记录](console-2101.json)，汇总见[summary.json](summary.json)。敏感配置行已遮盖。设备自带的时间显示与记录脚本的UTC可能采用不同的时区设置，记录时间以JSON中的UTC字段为准。

实际遇到的兼容性问题：此版本通过Console连接时不接受screen-length 0 temporary，返回接口类型须为VTY。采集改为识别分页并发送空格；异步系统日志可能出现在提示符之后，提示符识别也做了相应调整。

本次只验证从交换机发起的ICMP通信；没有伪称PC主动双向ping、VLAN故障恢复、保存后重启复现或10台设备的完整园区方案已经通过。3次探测不能用于推断长期丢包率、生产性能或切换时延。
